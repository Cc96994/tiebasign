# v0.6.0 M1 视觉证据（Before / After）

> 六张图都是**真实页面**（`app/main.py` 的 `_page_sign()` / `_page_sign_report()`）
> 用无头 Chrome 截的。签到页由 App 自己的 HTTP 服务渲染，页面里的 JS 真实调用
> `/api/sign/state`；报告页用真实 `report_text()` 渲染。账号、错误码和计数全部是
> 虚构的，不含任何真实 BDUSS、掩码或账号名。

## 场景与参数

- **Before** = `origin/main`（v0.5.6，提交 `0e34bbe`）；**After** = M1 分支。
- 签到页（`/sign`），同一份虚构状态：18 个待签吧，补签成功 15、服务端返回
  「今天已签到」3、失败 0，msign 成功、成长等级签到成功。视口 `500 × 1100`
  CSS px、`devicePixelRatio = 2`（输出 1000 × 2200），深色主题。
- msign 撞 `340011` 的场景：Before 是 0.5.6 的真实结果（18 个吧逐个补签全部
  失败，显示「补签失败 18」）；After 是 M1 的结果（风控即停，一个补签请求都
  没发，页面直接给错误说明）。视口同上。
- 报告页（`/sign/report`），同一份虚构报告：检查 17 个吧、成功 12、服务端返回
  已签到 2、失败 3（错误码 `111` / `340011` / `340006`），msign 失败进警告；
  `phase_ms` 为 login 1.2s / growth 0.9s / msign 2.8s / list 5.3s / sign 32.6s
  （请求 29.5s + 抖动 3.2s）。视口 `500 × 900` CSS px、DPR 2，深色主题。
- Before/After 使用同一份虚构数据；差异只有 M1 新增的「已签到」计数、文案，
  以及 S6 的风控即停。
